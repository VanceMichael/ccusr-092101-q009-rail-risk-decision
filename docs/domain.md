# 领域约定

购票账号、乘车人关系、支付主体、设备证明和处置决定使用脱敏引用。

外部主体一律使用不含真实身份信息的引用编号，时间采用带偏移量的 ISO 8601 字符串，附件只记录受控引用或 `sha256` 摘要。业务事件需要携带来源与序列号，后续实现应保留来源系统对事实的责任边界。

## 双服务边界

- **原执行节点（风控引擎，根服务）**：持有外部风控决定、模型内部字段（如 `rule_revision`）与各售票渠道实际限制状态。对申诉方只暴露 `/public/decisions/<ref>` 公开视图（可公开原因类别 + 渠道状态，不含任何阈值）与幂等指令端点。
- **申诉与解限后端（`appeal/`）**：独立数据库、独立部署。只保存 `decision_ref` 不可变引用与可公开原因类别；坐席看不到模型阈值，也不重做风险判断，只核实关系、支付与实名材料。

两服务之间只有两类交互：申诉侧只读公开视图；裁决/放行以携带 `Idempotency-Key` 的指令批次写回，原执行节点按键去重并返回逐项（渠道粒度）回执。

## 不可变性

申诉案件事件、复核意见、裁决一经写入即不可修改或删除（数据库触发器拒绝 UPDATE/DELETE）。终局结论长期保留，后续再犯产生新案件，不能抹去先前申诉为何成立。
